# Миграции SwiftData

Начиная с архитектурной фазы 3, AppTimer открывает локальное хранилище с явным `AppTimerSchemaMigrationPlan`. Исторические модели `Project`, `WorkSession`, `SessionProjectAllocation` и `AppSegment` закреплены как снимок `AppTimerSchemaV1`.

| Версия схемы | Содержимое | Назначение |
|---|---|---|
| `1.0.0` | Текущая устойчивая схема AppTimer, включая необязательное поле `WorkSession.note` | Базовая совместимая модель для уже сохранённых локальных данных. |
| `3.0.0` | Схема V1 и новый `ContextSegment` | Additive-схема Timeline для локальной opt-in истории приложений. |

Между V1 и V3 используется lightweight migration, поэтому данные не преобразуются и не удаляются. В первоначальном плане была промежуточная V2 с идентичной физической моделью V1. Она не является отдельной стадией: Core Data требует уникальный checksum на каждой стадии и прекращает запуск, если он повторяется. Версия 2.0.1 использует единственный безопасный переход V1→V3; хранилища, созданные при V2, имеют тот же legacy checksum и также мигрируют этим переходом.
