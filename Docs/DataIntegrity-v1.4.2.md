# AppTimer 1.4.2 — целостность локального учёта

## Цель

Версия 1.4.2 не добавляет новые пользовательские данные. Она гарантирует, что аварийное завершение процесса, перезагрузка Mac или закрытие приложения не превращают период отсутствия пользователя в рабочее время.

## Heartbeat активной сессии

Пока идёт учёт, AppTimer раз в 30 секунд сохраняет в `UserDefaults` компактную локальную запись: `WorkSession.id` и время последней подтверждённой активности приложения. Heartbeat обновляется также сразу после запуска учёта и при штатном завершении интервала. Запись удаляется только после успешного сохранения закрытой сессии с тем же идентификатором.

> Heartbeat не содержит имени проекта, содержимого окна, URL, текста или нажатий клавиш. Он существует только для ограничения длительности незакрытого интервала после аварийного разрыва.

## Восстановление на запуске

При загрузке локального хранилища AppTimer находит сессии без `endedAt`. Для каждой такой сессии он определяет последнее достоверное время как максимум из heartbeat, последнего завершённого сегмента приложения и начала сессии. Если разрыв до текущего времени превышает две минуты, сессия и её открытый сегмент закрываются этим временем. Если разрыв не превышает две минуты, сессия продолжается как активная.

| Сценарий | Поведение |
|---|---|
| Обычный выход из AppTimer | Сессия закрывается текущим временем до завершения процесса. |
| Аварийный выход, запуск через час | Сессия закрывается временем последнего heartbeat; пропущенный час не попадёт в отчёт. |
| Быстрый перезапуск до двух минут | Учёт продолжается без создания разрыва. |
| Старая открытая сессия без heartbeat | Сессия закрывается последним известным сегментом или временем запуска сессии; лишнее время не записывается. |

## Видимость для пользователя

После автоматического закрытия AppTimer показывает локальный баннер в Dashboard с точным временем закрытия. Пользователь может перейти к редактированию интервала или удалить его; баннер не отправляет уведомления и исчезает после закрытия приложения.

## Сохранение и ошибки

Запись в SwiftData выполняется через единый метод сохранения. При ошибке AppTimer записывает диагностическое сообщение через `Logger`, сохраняет понятный статус для интерфейса и не удаляет heartbeat. Это оставляет возможность корректно восстановить активную сессию после повторного запуска.

## Ручные сценарии проверки

| Проверка | Ожидаемый результат |
|---|---|
| Запустить учёт и закрыть AppTimer обычным способом | Сессия получает `endedAt` около времени выхода; heartbeat очищается. |
| Запустить учёт, аварийно завершить процесс, подождать более двух минут и открыть AppTimer | Сессия закрывается временем последнего heartbeat; Dashboard показывает баннер. |
| Аварийно завершить процесс и перезапустить меньше чем через две минуты | Незакрытая сессия продолжается как активная. |
| После баннера нажать «Править» или «Удалить» | Открывается существующий редактор интервала или удаляется именно восстановленная сессия. |
| Запустить AppTimer и не открывать Menu Bar | Сервисы конфигурируются из точки запуска приложения; отдельный клик не требуется. |
